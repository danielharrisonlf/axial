Gargalo encontrado: conexão TCP por requisição no gateway

O http-proxy usa agent: false por padrão: cada requisição proxiada abre e fecha uma conexão TCP com o microsserviço. Sob carga, isso gera handshakes, portas em TIME_WAIT, filas e erros. A correção foi um pool keep-alive compartilhado. Este teste sobe uma segunda instância do gateway sem keep-alive (porta 3100) e roda a mesma carga nas duas, com o mesmo código e na mesma máquina.

Pronto: GET /projects via gateway, 50 conexões, 10 s por lado.

Correções aplicadas

  1. Gateway: pool keep-alive compartilhado com os upstreams.
  2. APIs: gzip acima de 1 KB (auditoria −79%, tarefas −65%).
  3. Web: fontes self-hosted com font-display: optional.
  4. Web: code splitting por rota e remote do Insights sob demanda.

Compressão de payload

Gargalos remanescentes

  1. Gateway limita a vazão dos proxiados (~1,7–2,4k req/s). Próximo passo: cluster ou HTTP/2.
  2. Login é CPU-bound (scrypt, p50 ~69 ms) e tem rate limit de 20/min por IP, por segurança.
  3. Cache de /assets/* com immutable em produção.

Observabilidade dos serviços NestJS

Três camadas, todas ativas na demonstração. As duas primeiras são locais e não dependem de serviço externo.

1 · Métricas nativas

local

O pacote @axial/observability é registrado como middleware no gateway e no ms-projects. Ele mede cada requisição em um histograma fixo (O(1), memória constante) e expõe:

  • GET /api/v1/metrics: JSON com p50/p95/p99, vazão, taxa de erro, rotas, CPU, heap e atraso do event loop
  • GET /api/v1/metrics/prometheus: formato Prometheus, pronto para Grafana

Em produção, o endpoint só responde com METRICS_TOKEN.

2 · Logs estruturados

local

O ms-projects grava um log JSON por requisição (http_request) com método, rota, status, durationMs e x-correlation-id. O mesmo id volta no header da resposta, o que permite seguir uma requisição lenta do gateway até o serviço.

3 · NestJS Observe

—

SDK oficial de APM lançado com o NestJS 12 (@nestjs/observe), já integrado ao ms-projects. Gera traces por classe e método (guard → controller → service → query pg), erros agrupados e SLOs, em painel hospedado em observe.nestjs.com.

Desligado por padrão. Para ligar: crie uma conta grátis, defina OBSERVE_APP_KEY e OBSERVE_APP_SECRET no .env e reinicie o ms-projects. Painel de exemplo, sem cadastro: observe-demo.nestjs.com.
